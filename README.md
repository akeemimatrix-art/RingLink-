# RingLink

RingLink is an Android-first local service directory for Kampala, designed to expand across Africa. Customers discover verified service providers nearby, view professional profiles, and contact them. Providers can create a listing, add services, maintain availability, request verification, and request a listing subscription.

The repository contains the **Flutter application source, Supabase schema, seed data, tests, CI configuration and setup scripts** for the RingLink MVP foundation. It intentionally does not include Apple/iOS code, advertising, live payment-gateway credentials, or a carrier/VoIP provider.

## Product shape

### Customer

- Search providers and businesses.
- Filter by category and radius.
- View professional/business profiles.
- Call using the device dialer.
- Start an in-app text conversation with a provider.
- Save locations.
- Submit reviews after an accepted Ring/conversation.
- Create a Ring request for a category and nearby radius.

### Provider

- Create a professional profile.
- Choose a primary category and list additional services.
- Maintain availability and location.
- Request verification.
- Request a $5 individual listing subscription.
- Receive and accept/decline Ring requests.

### Business / Group foundation

- Create a business listing.
- Choose a main category and additional services.
- Maintain availability and location.
- Request a $9.99 business subscription.
- View a business dashboard.

Full team invitations and multi-member business administration are reserved for the next stage.

### Admin

- View platform metrics.
- Review verification requests.
- Approve/reject verification.
- Activate subscriptions for 30 days as an MVP admin bridge.

## Ring Engine foundation

The database implements the most important concurrency rule: **first provider to accept wins**.

At Ring creation:

1. Eligible verified/available/subscribed providers in the selected category and radius are inserted as participants (up to 25 for the MVP).
2. A provider can accept only while they are still in the `ringing` participant state.
3. The database locks the Ring row while processing an acceptance.
4. The first successful acceptance changes the Ring to `accepted`, records the winner and cancels the other participants in the same transaction.
5. A conversation is created automatically for the customer and winning provider.

This is the authoritative business rule. The mobile app polls the provider's incoming Ring queue in this MVP.

A real phone-like incoming Ring that can reliably wake/launch phones requires a production push/VoIP/telephony provider and platform-specific integration. It is deliberately not faked here.

## Stack

- Flutter (Android first)
- Supabase PostgreSQL
- Supabase Auth
- Supabase Storage
- Supabase Realtime for chat/ring-related realtime updates
- PostGIS for proximity queries
- `geolocator` for device location
- `image_picker` for profile/verification images
- `url_launcher` for phone dialer handoff

Supabase's current Flutter guide uses the project URL plus a publishable key for client initialization and recommends reviewing RLS before production. The repository follows that pattern and never embeds a service-role/secret key in the app. See: https://supabase.com/docs/guides/getting-started/quickstarts/flutter

## Prerequisites

Install:

- Flutter stable SDK
- Android Studio / Android SDK
- Git
- A Supabase project
- A Google Play Console developer account when you are ready to publish

Flutter's current documentation reflects the Flutter 3.47.x stable line as of August 2026.

## 1. Create the Supabase project

Create a Supabase project, then run these in the Supabase SQL Editor, in this order:

```text
supabase/migrations/202609230001_initial_schema.sql
supabase/seed.sql
```

The schema enables Row Level Security and stores verification documents in a private storage bucket.

## 2. Configure the app

Copy:

```text
config/dev.example.json -> config/dev.json
```

Replace the placeholders with your Supabase project URL and **publishable** key. `config/dev.json` is ignored by Git.

Run:

```bash
flutter run --dart-define-from-file=config/dev.json
```

For release automation, pass the same values through CI secrets/build-time Dart defines. Do not commit the real config file.

## 3. Generate the Android platform folder

The repository intentionally leaves out Flutter-generated Android boilerplate so it can be generated by your installed Flutter SDK.

Run:

```bash
bash scripts/bootstrap_android.sh
```

The script creates the Android platform and patches internet/location permissions plus compile/target SDK 36.

## 4. Install dependencies

```bash
flutter pub get
```

## 5. Run checks

```bash
bash scripts/check.sh
flutter analyze
flutter test
```

The GitHub Actions workflow also runs analysis/tests and a debug Android build using placeholder Supabase build-time values.

## 6. Create the first administrator

New accounts cannot self-assign `admin`. After creating your own account, run this once in Supabase SQL Editor using your Auth UUID:

```sql
update public.profiles
set account_role = 'admin'
where id = 'YOUR_AUTH_USER_UUID';
```

Only use this for an account you control.

## 7. Provider publishing rule

A provider is returned by the public directory RPC only when:

- provider profile exists;
- provider is available;
- provider is verified;
- an active, unexpired individual subscription exists;
- the provider has at least one active category service;
- location is present.

Businesses use the equivalent business listing rule.

## 8. Release build

After configuring a secure Android release/upload key:

```bash
flutter build appbundle --release --dart-define-from-file=config/dev.json
```

Keep keystores, passwords and signing secrets out of Git.

## Deliberately not included yet

These require a separate production integration or decision:

- Live Mobile Money/card recurring billing.
- SMS vendor configuration beyond Supabase Auth.
- True simultaneous incoming carrier/VoIP Rings.
- Push notification infrastructure.
- Automated KYC/identity vendor.
- Full company team invitations/roles.
- Production analytics/crash monitoring.
- Advertising.
- iOS/Apple build.
